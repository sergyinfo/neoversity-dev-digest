## What Works

- **2026-06-14** — `formatCost` (`src/lib/cost.ts`) distinguishes MISSING data (`null`/`undefined` → "—") from a genuine zero (`0` → "$0.00"), widens precision for sub-cent values (~2 sig figs), and trims trailing zeros to a 2dp floor ("$0.06" not "$0.060", "$0.0013" not "$0.00"). Reuse it for any per-run money display.

## What Doesn't Work

- **2026-08-02** — `@testing-library/user-event` is NOT a client dependency (only `jest-dom` + `react` are installed). Don't reach for `userEvent.setup()` in a component test — it typechecks against nothing and fails at import. Use `fireEvent` from `@testing-library/react`, the pattern already in use. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/FindingCard/FindingCard.test.tsx:2`.

## Codebase Patterns

- **2026-06-14** — Cross-route shared components live in `src/components/<Name>/` with an `index.ts` barrel, imported via `@/components/<Name>` (e.g. `RunCostBadge`, `diff-viewer`). Vendored UI primitives (`Badge`, `CircularScore`) live in `src/vendor/ui` under `@devdigest/ui` — different home. Evidence: `client/src/components/RunCostBadge/`.
- **2026-06-14** — The PR-list table is driven by two parallel constants that MUST stay length-aligned: `COLUMN_KEYS` (header keys + order) and `GRID` (CSS grid-template tracks). Adding a column = add to both AND render a matching cell in `PRRow.tsx`, else header/cells misalign silently. Evidence: `client/src/app/repos/[repoId]/pulls/constants.ts`.
- **2026-06-14** — i18n has only the `en` locale (`client/messages/en/`); new UI strings need a key under the right namespace file (e.g. `prReview.json`, `runs.json`) read via `useTranslations("<ns>")`. A missing key renders the raw key, not an error.
- **2026-08-02** — Features cut from the starter for the course leave working scaffolding behind — check for it BEFORE writing anything. The severity filter needed zero new primitives: `Chip` (`vendor/ui/primitives/Chip.tsx`) already had the design's exact API (`active/onClick/icon/count/color`), `SEV` (`primitives/tokens.ts`) had colour+icon+label per level, `s.divider` sat unused in `FindingsPanel/styles.ts`, `toggleGroup` already had `marginLeft:auto`, and the empty state already read "Adjust the filters above". Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/FindingsPanel/styles.ts`.
- **2026-08-02** — Findings are rendered PER REVIEW RUN, not as one flat PR-level list: `FindingsTab` → one `ReviewRunAccordion` per run → each owns its own `FindingsPanel` + state. Anything described as "on the PR page" for findings is per-run unless you lift state into `FindingsTab`. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/ReviewRunAccordion/ReviewRunAccordion.tsx:150`.

- **2026-08-23** — **`client/messages/en/blast.json` shipped in part-0 with zero readers**, holding the full copy for a Blast Radius card that did not exist: `stat.symbols|callers|endpoints|crons`, `view.tree|graph`, `callerCount`, `noDownstream`, `graph.empty`, `graph.ariaLabel`. Same pattern as the 2026-08-02 entry below. Before writing i18n keys for a lesson feature, check `messages/en/` for the file — the Tree/Graph toggle was specified there all along.
- **2026-08-23** — **The blast HTTP envelope is declared LOCALLY in `src/lib/hooks/blast.ts`, not imported from `@devdigest/shared`**, following the precedent `src/lib/hooks/repo-intel.ts` set for `RepoIntelState`. `client/CLAUDE.md` says contracts come from shared and must not be hand-duplicated — this is not a duplication: the map itself (`BlastRadius`) IS imported from shared; only the response wrapper, which does not exist there, is local. The reasoning is in `server/src/modules/blast/contract.ts`.
- **2026-08-28** — `SeverityBadge`/`SEV` (`vendor/ui/primitives/tokens.ts`) are keyed by a LOCAL finding-severity type (`CRITICAL | WARNING | SUGGESTION | INFO`) — note the shared contract's `Severity` in `server/src/vendor/shared/contracts/findings.ts:11` has only three values, no `INFO`. `RiskSeverity` (`contracts/brief.ts:74-75`) is a separate three-value enum (`high | medium | low`); the two do not interoperate, and passing one to the other's primitive does not typecheck. `WhyRiskCard/constants.ts:1-15` documents this explicitly and defines its own `RISK_META` + `Badge` rather than reusing `SeverityBadge` — the same shape `IntentCard/constants.ts`'s `CONFIDENCE_META` already used for `IntentConfidence` (2026-08-17 entry above). `Badge` + a local `*_META: Record<Enum, {color,bg,icon,labelKey}>` is now the standing pattern for rendering a categorical band as a WORD (WCAG AA) instead of reaching for a band-specific primitive. Evidence: `_components/WhyRiskCard/constants.ts` (`RISK_META`, used at `WhyRiskCard.tsx:103,117,207,211`), `_components/IntentCard/constants.ts:10-32` (`CONFIDENCE_META`, used at `IntentCard.tsx:69,77`).
- **2026-08-28** — `out_of_date` on `BriefResponse` is derived from the LOCAL half of the state fingerprint only (`server/src/modules/brief/service.ts:511-523`, via `describeMoved`) — an edited linked issue or reference document moves the remote half, which the read path cannot see by design (no outbound call on read). `WhyRiskCard` therefore deliberately offers Regenerate on EVERY rendered brief, current or not, rather than gating the button on the flag — its own comment explains that gating it "would leave a reader with no way at all to pick those edits up." Any future UI that DOES gate a regenerate affordance on `out_of_date` would remove that path. Evidence: `_components/WhyRiskCard/WhyRiskCard.tsx:52-56`.

## Tool & Library Notes

- **2026-08-02** — `client/specs/DevDigest Design (standalone).html` is the canonical design source, but `grep` finds NOTHING in it: the UI code is gzip+base64 inside a JSON resource map on a single 1.7 MB line (`<script type="__bundler/manifest">`, line 170). To read a component's reference implementation, JSON-parse that line and per entry `base64.b64decode` → `gzip.decompress`; the `text/javascript` resources come out as plain readable source (`FindingsPanel`, `Chip`, `SEV`, …). `file://` URLs are blocked in the browser tool, so decoding beats opening it.
- **2026-08-02** — The `Toggle` primitive renders `role="switch"`, so `screen.getByRole("switch")` is the stable handle in tests — it has no label text to query by. Evidence: `client/src/vendor/ui/primitives/Toggle.tsx:15`.
- **2026-08-17** — `ConfidenceNum` (`vendor/ui/primitives/ConfidenceNum.tsx`) is **percentage-only**: it takes a 0..1 float and renders `"87% conf"`. It is the wrong primitive for a confidence that is a categorical BAND (e.g. `PrIntentRecord.confidence` is `'high'|'medium'|'low'`) — mapping a band to a fake number just to reuse it reintroduces the invented precision the enum exists to avoid. Use `Badge` with `icon`/`color` and the level as a word (see `_components/IntentCard/constants.ts`).
- **2026-08-17** — The `Button` primitive's variant prop is **`kind`**, not `variant` (`kind?: "primary"|"secondary"|"tertiary"|"ghost"|"danger"`, `vendor/ui/primitives/tokens.ts:26`). `variant` typechecks as an unknown prop and fails the build, not silently.
- **2026-08-28** — `MonoLink` (`vendor/ui/primitives/MonoLink.tsx`) accepts only `children`/`onClick`/`href` — no `title`, `aria-label`, or `style` prop. Its `onClick` variant renders `<button className="mono">`, whose accessible name comes entirely from its children, and the `"mono"` class forces the monospace face onto every child, so prose must sit outside it. A middle-truncated path therefore needs an `srOnly` span carrying the full, untruncated value plus an `aria-hidden` span carrying the visible, truncated text — see `WhyRiskCard.tsx`'s `FileRef` (`:236-252`) and `FocusRow` (`:261-279`), which also note the button gets Enter/Space activation and tab order for free where a styled `<span onClick>` would not.
- **2026-08-28** — `.tnum` (`vendor/ui/styles.css:221-223`, `font-variant-numeric: tabular-nums`) is the vendored tabular-numerals utility class, and in practice the only legitimate reason a `_components/` component reaches for a bare `className` beside its `styles.ts` object — e.g. `WhyRiskCard.tsx` has exactly one `className` in the whole file, `"tnum"` at `:300`. Worth knowing before a "no raw classNames" grep flags a `tnum`/`mono tnum` usage as a Tailwind leak; it targets this vendored CSS file, not Tailwind.
